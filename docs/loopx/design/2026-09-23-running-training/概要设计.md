# 跑步训练建议 · 概要设计

状态：2026-09-23，用户已接受公开建议与密码解锁的加密私人报告；模型服务可配置。实现与验证见[详细设计](需求设计文档.md)。

## 已确认的需求

来源：本轮对话。只分析跑步，以提升有氧耐力、打基础和半马完赛为目标，每周可安排约 5 次；未设置比赛日期、成绩目标。公开展示近期分析与下一周建议，私人目标及解读只在解锁后展示。私人目标本身不写入公开源码、文档或测试。服务可在 Grok、GPT 等兼容接口间切换。

## 方案与边界

<a id="D-001"></a>
**D-001 · Behavior Contract · 已接受**：公开卡片包含近 28 天与前 28 天的跑步统计、分析依据、未来 7 天的训练目的/时长/强度/调整条件，以及报告日期。约 5 次是可用安排，不强迫近期训练不足的人立刻达到该次数。没有近期有效跑步数据时明确说明无法生成个性化安排。报告超过适用日期时标示过期。

<a id="D-002"></a>
**D-002 · Workflow Contract · 已接受方案的实现细化**：复用现有 Vite 数据投影和统一发布流程，构建时生成，页面只读；没有新增在线后台、数据库或定时工作流。统计由程序计算。公开与私人模型请求相互独立，公开请求不接收私人上下文。只发送日期、距离、时长、配速、心率覆盖情况与爬升摘要，不发送路线、地点、活动名称、账号或原始活动 ID。

数据流（箭头表示数据传递；新模块是训练报告生成与解锁）：

```text
既有活动 JSON → 既有规范化投影 → 跑步统计 → 公开 AI 请求 → 公开建议 ┐
                                      └→ 私人 AI 请求 → 加密 ───┤
                                           ↑                   ↓
                                    私人目标 Secret       单个报告 JSON
                                                               ↓
                                                  页面公开卡片 / 密码解锁
```

公开与加密输出必须全部成功才交给构建产物。启用生成后，配置缺失、请求失败、响应不合法或加密失败均终止构建；现有 `scripts/build.mjs` 保留上一份完整站点。未启用的本地/PR 构建展示统计与尚未生成状态，不伪装 AI 分析、不调用服务。

<a id="D-003"></a>
**D-003 · Data Contract · 已接受**：发布的私人报告只含密文；密码、API 密钥、私人目标与明文不进入仓库、日志、静态资源或浏览器存储。私人目标与必要摘要会发送到配置的 AI 服务，报告加密不隐瞒这一步。解锁仅发生在浏览器内存，手动锁定、离开页面/切换后台或刷新后需要重新解锁。

公开密文可被离线猜测密码，应使用密码管理器生成的长随机密码。改密码不撤回别人已下载的旧密文；此方案不是服务端账号控制。

## 架构适配与保护范围

`apps/running/plugins/activity-data.ts` 拥有只读规范化投影；`src/core/types.ts` 拥有活动合同；训练功能复用它们，不改历史 JSON、数据库、轨迹、活动筛选或展示纠正规则。新统计/加密/报告合同属于跑步应用的 `src/utils`，仅构建可见的生成器属于 `plugins`，两个主题共用一个卡片组件。原有同步与提交列表不变，报告仅存在于构建产物。

最接近的统计能力 `src/utils/yearSummary.ts` 面向自然年与年度演示；新需求使用固定长度的近期窗口和数据覆盖情况，因此独立增加小型统计函数，复用活动类型规范化，不改年度总结。最接近的数据发布扩展点是 Vite 插件，无需引入独立服务。新增维护成本是一个模型 JSON 合同、一种版本化加密格式与对应测试。

## 验证状态

设计推演已覆盖：混合活动、空数据、近期单次活动、部分缺失心率、模型失败、私人请求失败、错误密码、篡改密文、过期报告。实现与验证已完成，独立只读安全审查及修正后的复查未发现 Critical/Important 问题；实际验证范围与既有全站构建阻塞见[详细设计](需求设计文档.md)。仅使用纯文本数据流图，无渲染器依赖。Support lenses: none。
