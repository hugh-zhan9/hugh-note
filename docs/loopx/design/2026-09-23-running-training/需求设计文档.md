# 跑步训练建议 · 详细设计

来源与已接受范围：[概要设计](概要设计.md)。2026-09-23 建立；技术细节在已批准的静态加密报告方案内实施。

## 统计与接口

<a id="D-004"></a>
**D-004 · Data Contract**：新增 `/running/data/training.json`，不改变 `activities.json`。以 Asia/Shanghai 当日为截止日，当前窗口为含当日的 28 天，前一窗口为此前 28 天；使用活动的本地日期，避免运行机器时区影响。只纳入规范类型 `running`；距离或时长为零的记录不用于训练估算，并报告排除数。不把缺失心率当作零。平均配速按总时长/总距离计算，心率按有记录部分的时长加权，并显示覆盖次数。保留 8 个连续 7 天分组及必要的单次训练摘要供 AI 分析。

响应 `version=1`，包含 `generatedAt`、`summary`、`status`。`status` 为 `ready`、`disabled` 或 `insufficient-data`。只有 `ready` 含报告 ID、7 天适用日期、公开建议和私人密文。公开建议为受验证的 JSON 文本结构，不执行 HTML/Markdown。下一周包含连续 7 天，每天是跑步或休息，跑步天数至多 5。缺少模型结果、截断、拒绝、额外字段、非法类型和过长内容均拒绝。模型必须基于记录解释建议，不据配速推断疾病、恢复程度或保证成绩；没有实测阈值时不用精确心率分区。

<a id="D-005"></a>
**D-005 · Interface Contract**：模型通过 HTTPS 的 OpenAI-compatible Chat Completions 接口调用，地址和模型由配置指定；不自动降级或切换服务。JSON mode 只负责 JSON 语法，应用独立验证结构。每次请求有超时与响应大小上限，不重试，不输出请求或响应正文。公开请求只接收公共目标与统计，私人请求额外接收 Secret 中的上下文，并要求区分数据能支持的结论、研究证据和无法判断的部分；参考资料由私人上下文提供，模型不能凭空补出处。

配置：`RUNNING_AI_ENABLED=true` 时要求 `RUNNING_AI_BASE_URL`、`RUNNING_AI_MODEL`、`RUNNING_AI_API_KEY`、`RUNNING_REPORT_PASSWORD`、`RUNNING_AI_PRIVATE_CONTEXT` 全部存在。其余构建关闭 AI。密码至少 20 字符且不能全是数字，最多 256 字符；建议生成随机长密码。配置不可使用 `VITE_` 前缀。CI 仅在受信任的 main 非 PR 构建中注入秘密；PR 不调用模型。

## 私人内容保护

<a id="D-006"></a>
**D-006 · Data / Security Contract**：使用平台 Web Crypto 的 PBKDF2-SHA256（600,000 次、16 字节随机盐）派生不可导出的 AES-256-GCM 密钥，12 字节随机 IV、128 位认证标签；每次报告使用新的盐/IV。附加认证数据绑定报告 ID 与格式版本。密文封装固定版本/迭代次数/盐/IV/密文，解密前验证长度与格式。浏览器不保存密码、派生密钥或明文；关闭私人视图会使尚未完成的解密失效。

私人报告以固定标题和若干文本段展示，模型内容经过结构验证并由 React 转义。错误密码或被篡改时显示统一的解锁失败信息；加载失败与未生成状态区分，不影响地图、历史活动或公开统计。加密是发布边界，不保护已解锁设备，也不替代 AI 服务自身的数据处理政策。
