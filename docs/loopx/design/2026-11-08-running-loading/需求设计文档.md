# 跑步页面渐进加载

来源：2026-11-08 用户批准优化首屏加载、数据拆分和缓存，并明确“不想一打开就整个页面 loading”。用户后续明确授权提交并 push；沿用仓库既有自动发布流程，不改远端机器已有训练报告修改。Support lenses: none。

## D-1 页面与故障边界

沿用 App、Classic 路由、ActivitiesContext 和现有 ErrorBoundary。导航不依赖数据；HTML 自带与 React 共用的 LoadingShell，使脚本尚未下载时也有可用导航及分区占位。Classic 页面模块按路由加载，导航在数据 Suspense/ErrorBoundary 外；年度总结保留独立全屏样式，不显示站点导航。数据等待只影响内容，路线等待或失败只影响地图/预览，失败明确显示且可手动重试，不把未加载路线误报为无轨迹。

## D-2 数据与缓存

所有导出由现有 activity-data 插件从同一次 projectActivities 投影生成，Python 原始数据不变。

| 输出 | 使用方 | 内容 |
| --- | --- | --- |
| data/activities.json（保持原合同） | 博客、Dashboard、外部读取 | 全量活动和路线 |
| data/activity-index.<hash>.json | Classic 统计、列表、年度总结 | 全部历史活动元信息，summary_polyline 为 null，has_route 标识是否有轨迹 |
| data/routes-<year>.<hash>.json | 地图与按日路线预览 | 当年 run_id 到 polyline 的映射，仅有轨迹的记录 |

保留全量轻量索引，避免按年明细变更全站统计和地区筛选语义。仅路线按所选活动涉及的年份加载；不为列表或年度总结下载路线。Vite 虚拟模块将同次生成的 URL 注入前端，HTML preload 提前请求索引。内容哈希随内容变化，使用标准浏览器缓存，不强制每次校验。沿用模块内缓存并合并并发请求；失败不会永久污染后续手动重试。快速切换年份时旧请求不得覆盖新范围，空活动不发路线请求。

## D-3 兼容与验证

原接口、历史数据、全站月份/地区/类型筛选、run_id 深链接、年度总结、Dashboard 和配色行为保留。地图在元信息加载完后独立加载代码和当前范围路线；历史年份/全部/地区范围按实际匹配的活动确定年份。汇总路线预览复用同一个路线资源所有者，不新增持久存储或后台服务。

验证：插件对空/单项/跨年/非法数据/投影不变/哈希稳定性与变化的测试；资源加载并发、缓存、失败重试；人为延迟和失败时导航/列表仍可用、地图只在局部等待；真实数据的历史筛选和年度总结回归；类型检查、构建及必需仓库检查。未先见失败的核心逻辑做定向 mutation 检查。公共接口扩展完成后进行独立只读审查。

## D-4 发布兼容

沿用统一发布流程和 current-main gate，从当前发布仓库读取上一版资源。只保留其当前构建清单中的脚本、样式和带版本的活动数据，保留清单在复制旧资源前生成；不递归累积历史，不保留旧页面或训练报告。首次上线可从已有 Vite manifest 读取上一版资源；缺失文件或非法清单令发布失败，不静默发布不完整内容。
