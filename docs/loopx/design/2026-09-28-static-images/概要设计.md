# 静态图床 · 概要设计

状态：用户已授权实施纯静态、自带 GitHub Token 的方案；以下常规实现选择在该范围内。实现已验证；用户已授权提交并推送，发布状态以工作流记录为准。
来源：2026-09-28 当前对话；[详细设计](需求设计文档.md)。

## 已确认需求

- 图片与文章分仓，图片只新增，不删除、不修改。
- 参考 hugh-zhan9/lsky-pro 的上传体验，不直接引入其 PHP 代码和账号系统。
- 部署后的网页支持上传；用户输入自己创建、仅授权给图片仓库的 GitHub Token，并可更换。
- 当前任务完成实现与验证，不包含创建远程仓库、提交、推送或部署。

## 模块与数据边界

<a id="D-001"></a>
**D-001 · 架构合同**：新增 `apps/images` React/TypeScript/Vite 应用，入口 `/images/`，独立依赖与测试。复用根构建的暂存发布机制、全站颜色变量与主题控制器，不依赖跑步业务。图片固定存入独立 GitHub 仓库 `hugh-zhan9/hugh-image` 的 `main` 分支，浏览器直接调用 GitHub REST API。无服务器和数据库。

```text
当前仓库 ──组合构建──> 静态站点 /images/
                          │ 下载页面
                       用户浏览器 ──用户输入的 Token──> GitHub API
                          │                              │ 只创建
                          └──读取公开图片外链────────> 独立图片仓库
```

现有复用点：`scripts/build.mjs`、`assets/css/site-tokens.css`、`static/js/themetoggle.js`。兰空的 Blade 模板耦合 PHP 路由、用户组和数据库，且未提供 Git 存储驱动；只借鉴操作流程，不复制源码。保留 Hugo、跑步路由及数据合同；新增构建失败时保留此前完整站点。

<a id="D-002"></a>
**D-002 · 凭据合同**：Token 仅在当前页面内存中；刷新、离开或主动清除后消失。只向固定 `https://api.github.com` 发送 Authorization，不记录到日志、URL、浏览器存储或构建环境。仓库配置固定在代码中，不读取或写入浏览器仓库配置。GitHub Contents 写权限本身包含修改删除能力；只新增是本应用的行为保证。

## 上传与浏览

<a id="D-003"></a>
**D-003 · 行为合同**：支持选择、拖拽、粘贴、批量上传、预览、复制 URL/Markdown，以及仓库图片列表。输入校验和图片处理在写入之前执行；内容寻址和 GitHub 新文件创建保护已有文件。完整异常与并发规则见详细设计。

```text
选择图片 → 格式/大小校验 → 预览与压缩 → 内容哈希路径
                                          │
                              查询同路径 ─┼─ 相同内容 → 复用链接
                                          ├─ 不同内容 → 拒绝覆盖
                                          └─ 不存在 → 创建文件 → 返回链接
                                                        │
                                                    失败 → 显示错误
```

上传逐张进行，每张独立报告结果；某张失败不撤销已成功图片。提交成功表示已入库，使用 GitHub 原始文件外链。图片仓库需公开且先初始化分支；私有仓库不能提供无需凭据的公开外链。
